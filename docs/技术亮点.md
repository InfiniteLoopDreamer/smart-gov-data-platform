# 技术亮点与设计说明

> 面试叙事：用 NYC 311 真实热线数据，演示政务热线「受理 → 办件 → 督办 → 预测」闭环；对外说明时主动交代演示边界见文末。

## 1. 项目定位与架构

| 系统 | 技术栈 | 定位 |
| --- | --- | --- |
| 管理后台 | Vue 3 + Vite + Element Plus + ECharts | 登录鉴权、看板、工单、质量与预测 |
| API | FastAPI + SQLite | REST、RBAC、SQL 聚合 |
| 分析大屏（可选） | Streamlit + Pandas | 只读可视化，直读同一套库表 |
| 共享层 | `shared/` | metrics / auth / forecast / workflow |

数据叙事：**NYC 311 市民热线 → 映射为政务「诉求 / 办件 / 部门 / 区域」**，而非伪造国内业务库。

## 2. 数据模型（星型关联）

```
departments ──┐
              ├──> cases（办件）
regions   ────┴──> appeals（诉求）、inspections（巡查）
audit_logs / users / work_orders
```

- CSV 与 SQLite 双形态；后端启动时可 `ensure_db_from_csv()` 自动入库。
- 接入脚本：`import_nyc311.py`（抽样可复现演示）。

## 3. 认证与权限（可演示）

- 密码：PBKDF2；令牌：HMAC 签名 + 过期时间。
- 未登录访问业务接口 → **401**；`user` 调 `/api/users`、工单管理 → **403**。
- 前端：`router.beforeEach` 强制登录；axios 拦截 401 清态并跳转登录页。

## 4. 分析能力（shared）

- **Holt-Winters**（纯 numpy）：趋势 + 周季节，输出 MAPE / RMSE。
- **异常检测**：拟合残差 3-sigma，避免把正常高峰误判为异常。
- KPI / 趋势 / 部门排名 / 数据质量：纯函数，可单测。

## 5. 业务闭环

群众提交诉求 → `workflow` 工单状态机（待受理 → 分派 → 办理 → 办结）→ 政府端处置与督办超时。

## 6. 前端工程点

- `BaseChart.vue` 封装 ECharts 生命周期；看板 / 报表 / 趋势页只传 option。
- 开发默认端口 **5500**（规避 Windows Hyper-V 保留的 5173 段）；API 代理到 **8001**。

## 7. 工程化

- `tests/`：shared 单元测试 + `test_api.py` 冒烟（登录 / 401 / 403 / 看板 / 诉求）。
- 自动化验证：63 个 pytest 覆盖指标、预测、鉴权与核心 API，前端通过 Vite 生产构建检查。

## 8. 演示边界与口径说明

- 「系统设置」为演示 UI，不落库。
- Streamlit 大屏为可选只读视图，主链路是 **Vue ↔ FastAPI ↔ SQLite**。
- 令牌密钥为演示常量，上线应改为环境变量。
- README 中的区域分布 / MAPE 等数字基于 NYC 311 约 5 万条抽样；仓库不上传 `data/`，仅跑 `generate_data.py` 时指标会不同。
- 近 60 天异常日数量随样本波动，当前演示集可能为 0；应强调检测机制与质量规则，而非固定「揪出 N 个异常」。
