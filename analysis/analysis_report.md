# NYC 311 政务热线专题分析

## 1. 分析目标

基于 50,000 条 NYC 311 公开工单，回答三个实际问题：业务量主要集中在哪里、哪些事项最值得优先治理、短期办件量能否被稳定预测。`appeals` 与 `cases` 是同一批工单的两种业务视图，因此分析规模统一按 **50,000 条工单** 统计，不重复相加。

## 2. 核心发现

### 区域高度集中

布鲁克林区、皇后区、曼哈顿区分别约 17,032、14,137、10,087 件，前三大区域合计约 **82.5%**。有限人力应优先覆盖这三个区域，再结合事项结构细分排班。

### 头部事项贡献明显

堵塞车道与违章停车分别为 15,800 和 14,352 件，合计约占全部工单的 **60.3%**。相比平均分配资源，更适合建立交通类专项队列，并按区域监控积压量和办理时长。

### 数据质量总体可用，但区域映射仍需治理

关键字段完整度为 **99.36%**；共有 320 条区域为 `Unspecified`，另识别出 9 条“内容、分类、区域、时间”完全一致的重复记录。区域缺失会影响区域占比和资源调度结论，正式分析前应优先补齐或单独标记。

### 预测应以时间留出集而不是样本内拟合评价

使用前 21 天训练、最后 7 天留出评估 Holt-Winters 周季节模型，当前样本得到：MAPE **14.22%**、WAPE **14.01%**、MAE **117.98**、RMSE **139.30**。系统同时与“上一周同日”的季节性朴素法比较，并展示相对提升率与基于留出集 RMSE 的未来 7 天参考区间。该结果仅代表当前约 50 天窗口，后续仍应增加滚动回测。

## 3. 可执行建议

1. 将布鲁克林区、皇后区、曼哈顿区设为一级监控区域，按日跟踪办件量、未办结量和平均办理时长。
2. 为堵塞车道、违章停车建立交通类专项看板，分解到区域和星期，支持班次配置。
3. 对异常日期进一步使用“区域 × 事项”贡献度拆解，避免只报告异常、无法解释原因。
4. 将 `Unspecified` 区域和重复记录纳入每日质量规则，质量未达标时暂停发布区域 KPI。

## 4. 数据边界

- NYC 311 原始数据提供事项、区域、部门、状态、受理和办结时间。
- 中文名称为项目字段映射，不代表国内真实政务数据。
- 紧急程度、经办人、满意度、部门人员数等为界面演示字段，不作为本报告的业务结论。
- 样本只覆盖约 50 天，不支持年度同比、长期趋势或稳定季节性结论。
